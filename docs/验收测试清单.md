# SB Mod Manager 验收测试清单

面向真实数据的手工验收。**按顺序做**，每一轮的风险比上一轮高；
第 1、2 轮完全不碰你的 Mod 文件，可以放心试。

---

## 准备

### 启动

```
双击  D:\Code\Projects\ModManager\.venv\Scripts\stellar-mod-manager.exe
```

或者命令行：

```
cd D:\Code\Projects\ModManager
uv run stellar-mod-manager
```

### 出问题怎么反馈给我

1. 按 **F12** 打开内置日志查看器（或点右下角 ⓘ 图标）
2. 点「复制全部」，把内容贴给我
3. 如果弹了错误框，点「复制详情」

日志里有每次启动的会话头、你的操作记录和完整堆栈，我拿到就能定位。

### 测试期间的底线

| 操作 | 是否可逆 | 说明 |
|---|---|---|
| 分组相关（新建/改名/删除/移动） | ✅ 完全可逆 | 只改 `groups.json`，**不碰任何 Mod 文件** |
| 停用 / 启用 | ✅ 可逆 | 库里的副本始终保留 |
| 导入 | ✅ 只增不减 | 硬链接，不额外占空间 |
| **从库中删除** | ❌ **不可逆** | 本轮**不建议测** |
| 解压 | ⚠️ 写暂存目录 | 不改动 Mod |

> **先记下基线**，每轮做完回来对一眼，能立刻发现有没有意外改动。
> 建议先把这几个数填进文末的核对表。
>
> ⚠️ 如果你有真实在用的 Mod 库，强烈建议先整库备份一份再开始。
> 第 3 轮之后会真实改动游戏目录。

## 第 1 轮 · 只读验证（零风险）

### 1.1 启动与界面

- [ ] 窗口正常打开，无错误弹窗
- [ ] 左上角是**游戏图标**（EVE 头像）+ 名称 **SB Mod Manager**
- [ ] 任务栏 / Alt+Tab 里也是这个图标
- [ ] 标题栏显示 `SB Mod Manager`

### 1.2 库页数字

- [ ] 四张统计卡的数字与你的实际情况相符（库中 Mod / 已启用 / 仅存库中 / 实际占用）
- [ ] 实际占用**小于**「库 + 游戏目录」之和 —— 因为硬链接不重复计数

### 1.3 分组树（重点）

- [ ] 四个分组：服装、武器、玩法、其他
- [ ] 服装显示 **(92)**，武器 **(2)**，玩法 **(1)**，其他 **(1)**
- [ ] 武器/玩法/其他是**收起**状态（你之前折过），服装是展开的
- [ ] 点**整行**（不是小箭头）能折叠/展开
- [ ] 折叠状态在**关掉重开后仍然保持**

### 1.4 搜索

- [ ] 搜索框输入 `angel`，只剩匹配的 Mod
- [ ] 此时**所有分组自动展开**（即使之前是折叠的）
- [ ] 没有匹配项的分组会消失，不留空壳
- [ ] 清空搜索，恢复原状

### 1.5 筛选

- [ ] 下拉选「已启用」，只剩启用的
- [ ] 选「未纳管」，只剩游戏目录里、库里没有的
- [ ] 选「IoStore 格式」/「Pak 格式」能正确区分
- [ ] 选回「全部」

### 1.6 工具栏间距

- [ ] 搜索框与「全部」下拉之间**有明显间隙**，不贴在一起
- [ ] 「全部」与「+ 新建分组」之间的间隙**更大一点**（分组间隔）
- [ ] 没有「展开/收起」两个按钮了

### 1.7 主题

- [ ] 设置页 → 外观 → 切换深色/浅色
- [ ] 两套主题下**都没有白色/异常色块**（尤其滚动区域）
- [ ] 复选框选中时**有勾号**（✓），不是纯色方块

## 第 2 轮 · 分组管理（只改 groups.json）

### 2.1 新建分组

- [ ] 点「+ 新建分组」，输入 `测试分组`，确定
- [ ] 列表底部出现「测试分组 (0)」，在「其他」之后
- [ ] 再建一个同名 → **就地提示"同级已经有同名的分组了"**，确定按钮禁用
- [ ] 输入空白名 → 提示"分组名不能为空"

### 2.2 新建子分组

- [ ] 「服装」行右键（或点行尾 `...`）→「新建子分组…」
- [ ] 输入 `连衣裙` → 出现缩进的子分组
- [ ] **子分组比父分组更靠右**（层级方向正确）

### 2.3 移动 Mod 进分组

- [ ] 随便一个 Mod 卡片 → 点行尾 `∨` 菜单 →「移动到分组」
- [ ] 子菜单里有层级缩进，**当前所在分组带勾**
- [ ] 选「连衣裙」→ Mod 移到该子分组下，计数 +1 / -1 正确
- [ ] 再移回「未分组」

### 2.4 重命名

- [ ] 「测试分组」→ 重命名为 `改过名了` → 行上文字更新
- [ ] 取消重命名 → 名字不变

### 2.5 删除分组（安全，但会弹确认）

- [ ] 「改过名了」→「删除分组」→ 弹确认框
- [ ] 确认框里写清了**"Mod 文件本身不会被删除"**
- [ ] 确认后分组消失
- [ ] **对子分组试一次**：删掉「服装」，检查「连衣裙」是否**上提一级**变成顶层分组，
      且里面的 Mod **还在**（变成未分组），文件一个没少

### 2.6 自动分类（你已经跑过了，可选）

- [ ] 如果所有 Mod 都已归类，点「自动分类」应提示「所有 Mod 都已经分好类了」
- [ ] 若想重跑：先把若干 Mod 移回「未分组」，再点，应弹出预览框显示识别结果

## 第 3 轮 · 启停（动游戏目录，可逆）

> 这一轮会真实改动 `~mods`。做完记得对一下目录数。

### 3.1 单个停用 / 启用

- [ ] 挑一个**已启用**的 Mod（开关是蓝色），记下它的名字
- [ ] 关掉开关 → 提示成功；**库里那份还在**（打开库目录能看到）
- [ ] 打开 `~mods`，该 Mod 的目录**已经消失**
- [ ] 再打开开关 → 目录**回来了**，内容一样

### 3.2 硬链接不占空间（关键）

- [ ] 测试前记下 `D:` 剩余空间
- [ ] 停用再启用几个大 Mod（100 MB 以上）
- [ ] **`D:` 剩余空间基本不变**（差几十 MB 内），说明走的是硬链接而不是复制
- [ ] 库里任意一个 `.pak` 右键属性，**"占用空间"应远小于"大小"**（硬链接的特征）

### 3.3 整组启用 / 停用（★ 这是修过的 bug，重点测）

> 之前这个功能会因为参数写错直接崩，请务必试一次。

- [ ] 「武器」分组 → `...` 菜单 →「停用组内全部」
- [ ] **不崩溃**，弹确认框写明要停用几个
- [ ] 确认后出现进度，结束后提示「已停用 N/N 个 Mod」
- [ ] 组内 Mod 开关全部变灰，`~mods` 里对应目录消失
- [ ] 再「启用组内全部」→ 全部恢复
- [ ] 对一个**空分组**点「停用组内全部」→ 提示"这个分组里没有可管理的 Mod"，不报错

## 第 4 轮 · 导入（只增不减）

### 4.1 拖入压缩包

- [ ] 导入安装页 → 拖一个 `.zip` / `.7z` / `.rar` 进去
- [ ] 列表出现该文件，显示格式与大小
- [ ] 点「开始导入」→ 进度条走完，提示成功
- [ ] 回库页，新 Mod 出现，已在「未分组」里
- [ ] 库总数 +1，**`D:` 剩余空间基本不变**（同盘硬链接）

### 4.2 从文件夹导入

- [ ] 点「从文件夹导入…」，选一个已解压好的 Mod 文件夹
- [ ] 正确识别并纳入，**不额外占空间**

### 4.3 损坏文件（可选）

- [ ] 把某个 `.zip` 改坏（比如改名成 `.zip` 的文本文件）再导入
- [ ] 应显示该文件**失败**且说明原因，**其它文件照常成功**
- [ ] 提示是"N 个成功、M 个失败"而不是笼统的"完成"

---

## 第 5 轮 · 压缩包页与冲突检测

### 5.1 扫描与解压

- [ ] 压缩包页 → 选来源目录 → 「扫描」
- [ ] 空目录时显示**引导文案**（"还没有扫描"），不是一片黑表格
- [ ] 有压缩包时列出文件、格式、大小
- [ ] 勾几个 → 「解压选中项」→ 进度正常，结束提示成功/失败数量

### 5.2 冲突检测

- [ ] 库页 → 「冲突检测」→ 应调用 DekPakModAudit 并**在几秒内**出结果
- [ ] 结果按「ChunkID 冲突 / 覆盖原版资源 / 重复资源」分级
- [ ] 有冲突时顶部横幅是**中性底 + 左侧色条**（不是整块淡橙色）
- [ ] 可展开看是哪些 Mod 在争同一个资源
- [ ] 能复制纯文本摘要

---

## 第 6 轮 · 设置与诊断

### 6.1 设置项

- [ ] 六个卡片分成三组标题：目录位置 / 检测与行为 / 外观与关于
- [ ] 改「库位置」到别的盘 → 出现**跨盘提示**（会变成复制、占空间）
- [ ] 改回默认
- [ ] 行为开关改完**关掉重开仍然是新值**

### 6.2 日志与异常

- [ ] 右下角 ⓘ 或 `F12` 打开日志查看器
- [ ] 显示本次会话头（`SB Mod Manager v0.1.0 · 时间`）
- [ ] 级别筛选切到「仅错误」→ 只剩错误行
- [ ] 「复制全部」能复制

### 6.3 错误处理（可选，需要点手段）

- [ ] 随便找个能触发错误的操作（比如把游戏目录指向一个不存在的路径）
- [ ] 应弹**友好错误框**，有「复制详情」和「打开日志文件」，**程序不退出**

---

## 本轮**不建议**测的

| 功能 | 原因 |
|---|---|
| 从库中删除 Mod | **不可逆**。等你确认其它都稳了再单独试 |
| 安装 DekPakModAudit | 工具已就位，重装没必要 |
| 迁移旧数据 | 没有旧数据可迁 |
